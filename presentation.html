Masalah & Tantangan Lapangan

Mengapa Sistem Absensi Manual & Konvensional Harus Diganti?

Kehadiran pegawai outsourcing di Dinas Kependudukan dan Pencatatan Sipil Kab. Murung Raya memegang peranan krusial dalam pelayanan publik. Namun, beberapa kendala menghambat objektivitas evaluasi kinerja.

Potensi Manipulasi Tinggi

Absensi konvensional atau berbasis chat/foto biasa mudah dimanipulasi dengan pengiriman foto lama atau mock GPS lokasi palsu.

01

Ketidakakuratan Data Kehadiran

Sering terjadi fenomena "titip absen" atau melakukan pencatatan dari luar area kerja tanpa pengawasan langsung.

02

Ketiadaan Laporan Aktivitas Harian

Pengawas administrasi kesulitan mengetahui apa yang dikerjakan karyawan outsourcing setiap harinya secara objektif.

03

Proses Rekapitulasi Manual yang Lambat

Admin harus mencocokkan laporan kertas atau spreadsheet di akhir bulan, memakan waktu kerja yang berharga.

Solusi Sistem

Solusi Smart Absensi Pintar

Kami mengimplementasikan aplikasi web responsif (HP & Desktop) dengan sistem verifikasi ganda terdesentralisasi:

Biometric Face Verification

Menggunakan AI (Tensorflow.js) untuk mengekstrak face embedding biometrik wajah. Pengguna tidak bisa melakukan absen menggunakan foto orang lain.

GPS Geofencing

Membaca lokasi GPS real-time dan memverifikasinya di sisi server dengan rumus Haversine. Absensi ditolak jika jarak ke kantor melebihi 150 meter.

Daily Activity Journal

Karyawan wajib menulis ringkasan tugas harian sebelum diizinkan melapor pulang (Check-out), memberikan metrik produktivitas harian.

Keamanan Liveness Detection: AI melatih pendeteksian subjek hidup secara dinamis (liveness challenge) untuk menepis spoofing foto cetak atau layar handphone.
Fitur Aplikasi

Fitur Unggulan Sistem

Presensi Wajah & Liveness Detection

Pemrosesan deteksi wajah dijalankan langsung di browser sisi klien (Face-api.js) untuk menghindari pengiriman video mentah ke server (hemat kuota data). Menggunakan tantangan acak seperti "Tolehkan kepala" atau "Kedipkan mata" untuk memastikan keaslian pengguna.

Local Embedding Vektor 128-dimensi wajah diekstrak secara lokal. Kecepatan verifikasi < 1.5 detik.
Anti Spoofing Menolak foto di kertas, file digital di layar HP kedua, maupun topeng cetak.

Geofencing Validasi Jarak

Aplikasi mengambil koordinat GPS perangkat karyawan dan melakukan validasi jarak hipotenus dengan titik acuan kantor Disdukcapil (Latitude: -0.6225, Longitude: 114.5931). Server menghitung dengan rumus Haversine untuk ketepatan akurasi spasial.

Block Fake GPS Mendeteksi dan memblokir modifikasi lokasi melalui software Mock Location.
Radius 150m Batas area wajar yang mencakup seluruh bangunan kantor dan area parkir Disdukcapil.

Pengajuan Cuti & Verifikator QR

Karyawan dapat mengajukan izin sakit (dengan menyertakan SKD) atau cuti langsung di aplikasi. Saat disetujui admin, sistem menghasilkan Surat Cuti digital berformat PDF yang disisipi kode QR unik yang dapat dipindai publik untuk verifikasi keabsahannya.

Public Verification Portal Siapapun dapat memindai QR code di surat untuk membuktikan keaslian dokumen di server.
Bebas Pemalsuan Mencegah manipulasi surat izin dinas manual oleh oknum tidak bertanggung jawab.

Dashboard & Laporan Otomatis

Admin dapat melihat sebaran presensi harian, grafik keterlambatan, tabel detail log datang/pulang beserta foto bukti wajah, serta lokasi absen di peta interaktif Leaflet.js. Admin juga dapat mengunduh laporan PDF bulanan per karyawan lengkap dengan akumulasi rekapitulasi.

Ekspor CSV / PDF Cetak laporan format Excel dan PDF bulanan secara instan untuk bahan evaluasi.
Manajemen Shift & Libur Mengatur batas waktu shift (Pagi/Malam) dan menetapkan kalender hari libur nasional.

Alur Kerja

Diagram Alur Pengguna (User Flow)

Perjalanan Pegawai Harian

  • Login Akun: Pegawai masuk menggunakan email dinas dan sandi terdaftar.
  • Lapor Datang: Memberikan izin GPS & kamera, deteksi wajah, dan kirim presensi (Hadir/Terlambat).
  • Jurnal Pekerjaan: Sebelum pulang, pegawai mengetik pekerjaan harian yang terselesaikan.
  • Lapor Pulang: Menekan lapor pulang dengan pemindaian biometrik & GPS yang sama.
Catatan kehadiran tersimpan otomatis di Neon PostgreSQL.

Alur Kerja Admin & Pengawas

  • Pantau Real-time: Admin login dan melihat KPI hari ini (jumlah hadir, terlambat, luar radius).
  • Verifikasi Bukti: Melihat visual foto wajah selfie & sebaran radar lokasi GPS karyawan.
  • Kelola Sistem: Mengedit daftar pegawai, shift jam kerja, libur, dan persetujuan cuti.
  • Laporan Bulanan: Cetak rekap bulanan & jurnal laporan pekerjaan PDF per karyawan.
QR code di Surat Cuti dapat divalidasi langsung oleh pihak luar lewat scan kamera HP.
Spesifikasi Teknis

Arsitektur & Tech Stack

Frontend Responsif

HTML5, Vanilla CSS (Aurora Dark), Leaflet.js (Map), face-api.js (TensorFlow Client-Side biometrics).

Serverless Backend

Node.js Express API di-deploy ke Vercel Serverless Functions. Menangani hitungan jarak GPS server-side & generate PDF.

Database Cloud Serverless

Neon PostgreSQL. Menjamin ketahanan transaksi data, skalabilitas instan, dan performa query database relasional yang cepat.

Skema Database PostgreSQL

users Master
attendances Relasi

permits Relasi

TABEL: users (Menyimpan akun Karyawan dan Admin)

Kolom Tipe Data Atribut Deskripsi
id UUID PRIMARY KEY ID unik untuk setiap pengguna.
name VARCHAR(100) NOT NULL Nama lengkap pegawai / pengawas.
role VARCHAR(20) NOT NULL Status akun: 'karyawan', 'admin', atau 'pengawas'.
email VARCHAR(100) UNIQUE Email dinas untuk masuk sistem.
password VARCHAR(255) NOT NULL Kata sandi terenkripsi (bcrypt).
face_embedding TEXT NULLABLE Vektor string representasi matematika wajah pegawai.

TABEL: attendances (Menyimpan riwayat absensi harian)

Kolom Tipe Data Atribut Deskripsi
id UUID PRIMARY KEY ID unik riwayat presensi.
user_id UUID FOREIGN KEY Relasi ID pengguna ke tabel users.id.
date DATE NOT NULL Tanggal presensi dilakukan.
check_in_time TIMESTAMP NULLABLE Waktu persis melapor datang.
check_out_time TIMESTAMP NULLABLE Waktu persis melapor pulang.
photo_url TEXT NOT NULL Tautan foto bukti selfie presensi.
latitude_longitude VARCHAR(100) NOT NULL Koordinat GPS (lat,lng) saat melakukan presensi.
status VARCHAR(50) NOT NULL Status: 'Hadir', 'Terlambat', 'Luar Radius', 'Gagal Verifikasi'.

TABEL: journals (Laporan uraian tugas kerja harian)

Kolom Tipe Data Atribut Deskripsi
id UUID PRIMARY KEY ID unik jurnal laporan pekerjaan.
user_id UUID FOREIGN KEY Relasi ID pengguna ke tabel users.id.
date DATE NOT NULL Tanggal penulisan jurnal laporan.
task_description TEXT NOT NULL Uraian lengkap teks tugas yang diselesaikan karyawan.

TABEL: permits (Data permohonan izin sakit & cuti)

Kolom Tipe Data Atribut Deskripsi
id UUID PRIMARY KEY ID unik data pengajuan cuti/izin.
user_id UUID FOREIGN KEY Relasi ID pengguna ke tabel users.id.
permit_type VARCHAR(20) NOT NULL Jenis: 'izin' (tidak masuk), 'sakit', atau 'cuti'.
start_date DATE NOT NULL Tanggal mulai awal izin / cuti dinas.
end_date DATE NOT NULL Tanggal berakhir selesainya izin / cuti.
reason TEXT NOT NULL Alasan logis pengajuan yang diajukan pegawai.
status VARCHAR(30) NOT NULL Status saat ini: 'pending', 'approved', atau 'rejected'.
Deployment

Deployment ke Vercel & Neon DB

Setup Database Neon: Daftar di Neon.tech dan buat database PostgreSQL instan. Dapatkan string koneksi database.
Hubungkan Git Repo: Push folder source code absensi ini ke repository GitHub Anda.
Deploy di Vercel: Hubungkan GitHub repo ke Vercel, lalu isikan variabel lingkungan DATABASE_URL dengan koneksi string Neon.
Inisialisasi Skema: Akses rute khusus https://domain-vercel.app/api/setup sekali untuk membuat seluruh tabel & data akun awal.
.env.example
# Neon PostgreSQL Connection URL
DATABASE_URL="postgresql://admin:xxxxxx@ep-cool-pool-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require"

# Default App Configuration

OFFICE_LONGITUDE=114.593100
OFFICE_RADIUS_METERS=150
